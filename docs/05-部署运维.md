# 部署与运维

## 1. 服务器基线

| 阶段 | 规格 | 承载 |
|---|---|---|
| 起步 | 4C8G / 40G SSD / 5Mbps | ≤ 500 账号（全栈单机 compose） |
| 成长 | 8C16G + 2C4G(agent 独立) | ≤ 2000 账号 |
| 规模化 | 托管 PG + 托管 Redis + agent 横向 N 台 | 无上限（瓶颈在出口 IP 池） |

系统：Ubuntu 24.04 LTS。**只开 22/80/443**，PG/Redis/MinIO 只绑 127.0.0.1 或 docker 内网。

## 2. 目录布局（服务器）

```
/opt/ykt-ops/
├── docker-compose.yml
├── .env                 # chmod 600, root
├── deploy/nginx/        # 反代配置
└── data/{pg,redis,minio}  # bind mount，纳入备份
```

## 3. 首次部署

```bash
# 1) 基础
apt update && apt -y install docker.io docker-compose-v2 git ufw fail2ban
ufw allow 22,80,443/tcp && ufw --force enable

# 2) 取代码
git clone <repo> /opt/ykt-ops && cd /opt/ykt-ops

# 3) 生成主密钥（32B）
openssl rand -base64 32 | tee /opt/ykt-ops/.yk_master_key && chmod 600 /opt/ykt-ops/.yk_master_key

# 4) 配置
cp .env.example .env && vi .env      # 填 DSN / REDIS / MASTER_KEY / LLM keys
chmod 600 .env

# 5) TLS（证书放 deploy/nginx/certs 或用 certbot）
docker compose --profile tls run --rm certbot certonly --standalone -d <domain>

# 6) 起服务
docker compose up -d --build
docker compose exec api /app/migrate up

# 7) 建首个 admin
docker compose exec api /app/ykt admin create --email user@example.com
```

## 4. compose 拓扑（见 `deploy/docker-compose.yml`）

| 服务 | 端口 | 说明 |
|---|---|---|
| nginx | 80/443 | 反代 + 静态 |
| api | 8080(仅内网) | 2 副本起 |
| scheduler | — | 单实例 + PG advisory lock 选主 |
| agent | — | 1..N 副本，`YKT_AGENT_CONCURRENCY` 控制 |
| postgres | 5432(内网) | 挂 `./data/pg` |
| redis | 6379(内网) | AOF everysec |
| minio | 9000(内网) | 留证对象存储 |

## 5. 环境变量

见 `.env.example`。关键项：

| 变量 | 必填 | 说明 |
|---|---|---|
| `YKT_MASTER_KEY` | ✅ | base64(32B)，凭据加密主密钥，**丢失=所有 cookie 不可解** |
| `YKT_DB_DSN` | ✅ | `postgres://user:pass@postgres:5432/ykt?sslmode=disable` |
| `YKT_REDIS_ADDR` | ✅ | `redis:6379` |
| `YKT_JWT_SECRET` | ✅ | 32B 随机 |
| `YKT_AGENT_CONCURRENCY` | | 默认 300 |
| `YKT_LLM_PROVIDERS` | | `deepseek,qwen,glm`，缺省降级为"仅题库" |
| `YKT_PROXY_POOL` | | socks5 列表，逗号分隔 |

## 6. 备份（每日 03:30）

```bash
# /opt/ykt-ops/backup.sh  (cron: 30 3 * * *)
docker compose exec -T postgres pg_dump -U ykt ykt | gzip > /backup/ykt-$(date +%F).sql.gz
tar czf /backup/minio-$(date +%F).tgz -C data minio
find /backup -mtime +14 -delete
# 异地：rclone copy /backup remote:ykt-backup
```
**恢复演练每季度一次**：新机器 `up` → `psql < dump` → 校验 `accounts` 解密可读。

## 7. 监控与告警（Prometheus + Grafana + Alertmanager）

必配指标：
- `ykt_checkin_total{result}` 签到成功率（**SLO ≥ 98%**，5min 窗口）
- `ykt_sign_duration_seconds` 签到耗时 P95（**SLO ≤ 5s**）
- `ykt_quiz_latency_seconds` 答题提交距 deadline 余量 P50（**SLO ≥ 8s**）
- `ykt_ws_connections` 在线连接数 / `ykt_ws_reconnects_total`
- `ykt_session_expiring_48h` 即将失效账号数
- `ykt_queue_lag_seconds` stream 积压
- `ykt_upstream_error_ratio{domain}` 上游错误率（>20% 熔断）

告警通道：企业微信机器人 + 短信（P0）。值班口径：
| 级别 | 条件 | 响应 |
|---|---|---|
| P0 | 签到成功率 < 90% 持续 10min / 全线 50001 | 立即，5min 内确认 |
| P1 | 单域名族错误率 > 20% / 队列积压 > 5min | 15min |
| P2 | 单账号连续失败 3 次 / session 到期潮 | 当天 |

## 8. 扩容与灰度

**扩 agent**：`docker compose up -d --scale agent=4`（无状态，队列自动分片）。上限 = min(CPU 核数×0.8, 出口 IP 数×25)。

**协议改版灰度**：
```sql
INSERT INTO domain_profiles (...) VALUES ('pro.yuketang.cn', 'v3.2', ...);
-- 先只对 1 个测试账号启用：accounts.proxy_id 不动，用 ops 接口灰度单账号
```
步骤：单账号验证 → 5% 账号 → 全量。每步观察 30min 签到成功率。

**回滚**：`UPDATE domain_profiles SET enabled=false WHERE domain=...` 立即生效，无需重启。

## 9. 安全运维清单

- [ ] `.env` 600，属主 root；`docker inspect` 不泄露（用 `env_file` 而非 `environment`）
- [ ] 数据库每日备份 + 异地；`YKT_MASTER_KEY` 单独离线备份（打印/密码管理器）
- [ ] nginx 限流：`limit_req_zone` 登录 5r/m、下单 10r/m
- [ ] fail2ban 盯 nginx 4xx、ssh
- [ ] 管理后台加 IP 白名单或强制 2FA
- [ ] 每季度轮换 `YKT_MASTER_KEY`（多 key_version 共存，后台批量重加密）
- [ ] 日志保留 30 天，含 cookie 行必须为 0（有单测兜底）

## 10. 停机与销毁

```bash
docker compose down            # 停服务，保留数据
docker compose down -v         # 连卷删除（不可恢复）
# 用户注销：DELETE /accounts/{id} → 物理删除密文；30 天后删审计外的行
```
