# ykt-ops 架构设计

> 版本 v0.1 ｜ 状态：定稿待评审 ｜ 更新 2026-11-16
> 一句话：**多租户的雨课堂考勤/答题自动化平台。用户网页下单，服务端托管其账号凭据，按课表 7×24 代为提交到、代答随堂小测、代为提交位置签到。**

---

## 1. 目标与非目标

### 目标
| # | 能力 | 验收口径 |
|---|---|---|
| G1 | 网页下单 | 注册 → 扫码绑号 → 选课 → 付款 → 自动开通，全程无需人工 |
| G2 | 自动签到 | 课堂开始/教师开签到后 ≤ 5s 内提交，成功率 ≥ 98% |
| G3 | 随堂小测 | 题目下发 → 提交 ≤ deadline-8s，题库命中率 ≥ 70% |
| G4 | 定时长期跑 | 单账号连续在线 ≥ 14 天（session 生命周期内），掉线自动重连 |
| G5 | 任意时间 | 调度粒度 30s，支持临时加课/调课 |
| G6 | 位置签到 | 支持 GPS 签到（协议待抓包确认，接口先留位） |

### 非目标
- 不做刷课（看视频/挂时长）——开源已有成熟实现，与本平台上游限流模型冲突，不上。
- 不做代考/代写作业（大作业、考试）——只做课堂内的实时签到与小测。
- 不自建 App，不协议分析客户端加密，只用 Web/小程序可见的 HTTP + WSS 面。

---

## 2. 约束（决定了整个架构的形状）

| 约束 | 影响 |
|---|---|
| **Session 有效期 2 周** | 必须有"到期前 T-3 天推送重扫"闭环 + 失效账号自动冻结计费 |
| **协议频繁改版** | 协议层必须 adapter 化、版本化，与业务解耦，支持热切换 |
| **上游限流**（同 IP 多号、UA、时间整齐） | 一账号一出口代理、请求抖动、UA/指纹池、QPS 上限 2 |
| **实时性**（签到窗口 30~60s） | 长连接常驻，不轮询；调度提前 5 分钟拉起 |
| **凭据是明文 cookie** | 信封加密 + 主密钥外置 + 全链路脱敏 |
| **合规高压** | 全链路留证 7 天（可举证"我做了什么"）、熔断开关、单租户可独立停服 |

## 3. 进程拓扑

```
                    ┌──────────────┐
   浏览器 ──HTTPS──▶ │  nginx       │ ── /api ──▶ ┌─────────────┐
                    │  TLS + 静态   │             │  api 服务    │  (Go, N 副本)
                    └──────────────┘ ── /*  ──▶   │  下单/绑号/  │
                                                 │  管理/SSE    │
                                                 └──────┬──────┘
                                                        │ 读写
                        ┌───────────────┬───────────────┼──────────────┐
                        ▼               ▼               ▼              ▼
                  ┌──────────┐   ┌───────────┐   ┌──────────┐  ┌───────────┐
                  │ Postgres │   │  Redis    │   │  MinIO   │  │ 外部: 雨课堂 │
                  │ 事实库    │   │ Stream+锁 │   │ 证据日志  │  │ + LLM + 代理 │
                  └──────────┘   └─────┬─────┘   └──────────┘  └───────────┘
                                       │ XADD / XREADGROUP
                                       ▼
                  ┌──────────────────────────────┐
                  │  agent 池 (无状态, N 副本)     │  一进程 ≈ 300 并发 wss
                  │  签到链 / 答题链 / 重连 / 留证  │
                  └──────────────┬───────────────┘
                                 ▲ 唤醒
                  ┌──────────────┴───────────────┐
                  │  scheduler (单实例 + 租约锁)   │  课表 → 下一唤醒时刻 → 投递
                  └──────────────────────────────┘
```

**四个可部署单元**：`api`、`scheduler`、`agent`、`web(nginx+静态)`。共享 Postgres + Redis + 对象存储。

## 4. 模块划分与依赖方向

六边形：**domain 不依赖任何外部**，adapter 在边缘。

```
internal/
  domain/        纯类型与规则：Account, Lesson, CheckinTask, QuizProblem, SignPolicy, AnswerPolicy
                 （零 import 外部包，全部单元测试覆盖）
  ykt/           协议层（出站 adapter）：HTTP 客户端 + WSS 客户端 + 各域名族 profile
    protocol/    wire DTO 与端点常量
    profile/     每域名族的差异（source 值、header、字段名）
  store/         仓储接口（port）+ pg 实现 + memory 实现（dev/test）
  queue/         任务队列接口（port）+ redis stream 实现 + memory 实现
  llm/           答题 provider 接口 + 3 家实现 + 投票合并
  proxy/         出口代理池（socks5/http），按账号粘性分配
  crypto/        信封加密（AES-256-GCM），主密钥来自 env/KMS
  obs/           日志、指标、request_id、脱敏
  httpx/         路由、JSON 信封、中间件、错误映射
  config/        环境变量加载 + 校验（fail fast）
cmd/
  api/  scheduler/  agent/
```

**依赖规则（CI 强制）**
1. `domain` 只能 import stdlib。
2. `ykt`、`store`、`queue`、`llm`、`proxy` 不得 import `httpx`。
3. `cmd/*` 是唯一允许组装全部依赖的地方。
4. 任何跨层调用走接口，不直接 new 具体实现。

## 5. 关键设计决策（ADR）

### A1 模块化单体 + 三类进程，不拆微服务
理由：单团队、协议耦合高、跨服务调试成本 >> 收益。agent 天然无状态可水平扩，已经解决唯一的扩容瓶颈。拆微服务只会在协议改版时制造多版本地狱。
代价：api 与 scheduler 必须一起发布。用"同一镜像、不同 entrypoint"缓解。

### A2 用 Go 重写协议，不复用 Python 开源代码
理由：单机 300 并发 wss，Python 需要 300 个协程 + GIL 下的 JSON 序列化热点；Go 每连接约 30KB，4C8G 单机可跑 800~1000 账号。开源代码只当作**协议说明书**读，不 vendor。
代价：重写 12 个端点（约 800 行），已在调研阶段把 wire 细节全部提取完毕。

### A3 agent 无状态 + Redis Stream 任务队列
任务 = `{task_id, account_id, lesson_id, kind, deadline}`。agent 用 `XREADGROUP` 消费，用 `XACK` 确认；超时未 ack 自动重新投递（PEL + `XAUTOCLAIM`）。任务幂等键 `(account_id, lesson_id, kind)`，DB 唯一索引兜底"最多一次签到"。

### A4 凭据信封加密，主密钥永不落库
`ciphertext = AES256GCM(DEK, cookie)`；`DEK = AES256GCM(MASTER_KEY, random_dek)`；DB 只存 `ciphertext + wrapped_dek + key_version`。`MASTER_KEY` 从 `YKT_MASTER_KEY`（32B base64）注入，支持轮换（多版本共存）。
**红线：任何日志、panic、trace 不得出现 cookie 明文；`obs.Redact()` 在 slog handler 层强制。**

### A5 协议 adapter 版本化
`domain_profile` 表存 `{domain, protocol_version, source_checkin, headers_json, field_map_json, enabled}`。改版时新增 profile 行、置旧行 `enabled=false`，**不改代码不重启**。代码里只保留 wire 语义，不硬编码 source 魔法数。

### A6 签到策略链（fail-fast 到 fail-soft）
```
进入课堂签到(source=profile.checkin_source)  ──成功──▶ 完成
        │失败(LESSON_END 直接终止)
        ▼
  暗号签到(有 inviteCode 时)
        ▼
  动态码(ticket 由 fetch-dynamic-invitation 或用户上传获得)
        ▼
  位置签到(有 lat/lng 且 profile 支持)
        ▼
  全部失败 → 告警 + 计费不计次 + 人工介入队列
```
每一步有独立超时（3s）与重试上限（2 次），总预算 < 25s。

### A7 答题策略链
```
题库精确命中(同 problemId)  ──▶ 直接提交
   ▼ miss
共享池(同课堂 + 题干 hash 相似度 ≥ 0.92)──▶ 提交 + 计入题库
   ▼ miss
LLM 三路并发(deepseek/qwen/glm)，多数票；不一致取置信最高
   ▼ 超时(deadline-25s 仍未定)
按题型兜底(单选 A / 多选全选 / 填空空串)，标注 low_confidence 供事后申诉
```
时间用 wss 帧 `dt` 校正的服务器时钟，**提交时刻 = deadline - random(8,15)s**。

### A8 全链路留证
每个 lesson 一条 `lesson_trace`：请求/响应摘要（脱敏）+ wss 帧时间线 + 提交结果，落 MinIO，TTL 7 天。用于：争议举证、协议回归回放、限流自检。

## 6. 核心时序

### 6.1 绑定账号
```
用户 → api: POST /v1/accounts/bind/start
api  → 雨课堂 wss: {op:requestlogin,type:qrcode} → ticket
api  → 用户: {bind_ticket, qr_url}   (前端渲染二维码，页面轮询 bind/status)
用户 扫码 → 雨课堂 → wss 回 {UserID, Auth}
api  换 cookie → 校验 /api/v3/user/basic-info → 加密入库 accounts
```

### 6.2 一次签到
```
scheduler(每 30s):
  SELECT 未来 10 分钟内开课的 lesson → XADD task{kind=warmup, at=start-5m}
agent:
  warmup  → 拉起 wss 常驻，checkin → 拿 lessonToken → 转 listening
  listening→ 帧 showpresentation/unlockproblem → quiz 子任务
          帧 签到相关 → 走策略链
  lessonfinished → 关闭连接，写 lesson_trace，结算
```

### 6.3 会话保活
``` 
每 4h: GET /api/v3/user/basic-info
  code!=0 → 标记 expired → 推送重扫 → 冻结计费
  过期前 T-3 天 → 推送提醒
```

## 7. 容量与规格

| 项 | 数值 | 依据 |
|---|---|---|
| agent 单副本并发 wss | 300 | Go，内存 ≈ 300×40KB + runtime ≈ 120MB |
| 单机（4C8G）账号承载 | 800~1000 | 1 副本 agent + api + pg + redis 共存（小规模） |
| Postgres | 2C4G，日增 < 200MB | 每账号每天约 3 课 × 20 行 |
| Redis | 512MB | stream + 锁 + 缓存 |
| 单课算力 | 答题 3 次 LLM 调用 | 按 5% 课程有 10 题估算 |

规格建议：起步 `4C8G / 40G SSD / 5Mbps`；1000 账号以上把 agent 拆到独立 2C4G 机器。

## 8. 失败模式与降级

| 失败 | 检测 | 处置 |
|---|---|---|
| 雨课堂改版（字段变） | 端点 4xx 率 > 20% 持续 5min | 熔断该 domain_profile，全量告警，不影响其他域名族 |
| session 失效 | basic-info code≠0 | 该账号任务暂停 + 推送重扫，不计费 |
| 代理不可用 | 拨号失败 3 次 | 换池内下一代理；无可用代理则该账号任务排队不投递 |
| LLM 全挂 | 三路均超时 | 兜底提交 + low_confidence 标记 |
| agent 崩溃 | 心跳丢失 60s | Redis PEL 重新投递；同一 task 最多重投 3 次 |
| 重复签到 | DB 唯一索引冲突 | 视为成功，跳过（幂等） |

## 9. 未来扩展位

- 位置签到协议落地 → 只需新增 `profile` 行 + `SignPolicy` 的一步。
- 多平台（学习通）→ `ykt/` 抽象成 `platform/`，domain 不变。
- 反代池扩容 → `proxy` 接口加订阅源即可。
