# 16 · 按课程自动签到（课程级开关）

## 为什么不是「课堂级任务」
原来的巡检只有两种东西：
- 全局通配任务：`tasks.classroom_id='*'`，全天候签**所有**进行中课堂；
- 课堂级任务：`classroom_id` 写死某一节课的实例 ID（如 26000003），加一条删一条，没有开关。

用户要的是「哪门课要签、哪门课不签」——粒度是**课程名**（大学物理C、大学英语BⅢ），不是某一节课的实例 ID，同一门课每周 cid 也会变。所以新增第三类任务：**课程任务**。

## 数据模型
`tasks` 表新增 `subject TEXT`（`biz.init()` 里 `PRAGMA table_info(tasks)` 检查后 ALTER，幂等）。

课程任务的 `classroom_id` 用命名空间 **`subj:<课程名>`**，例如 `subj:大学物理C`。

> 踩坑：`tasks` 有 `UNIQUE(acct, classroom_id)`。最初把课程任务也写成 `classroom_id='*'`，第二门课直接 `UNIQUE constraint failed: tasks.acct, tasks.classroom_id`。改成 `subj:` 前缀后天然唯一，且不动既有数据。

## 调度器语义（app.py scheduler()）
```python
_cid0 = str(td["classroom_id"]).strip()
wild  = _cid0 in ("*", "ANY", "any", "all") or _cid0.startswith("subj:")
subj  = str(td.get("subject") or "").strip() or (_cid0[5:] if _cid0.startswith("subj:") else "")
```
- 课程任务按 wild 处理（走 `srv.live_all(acct)` 拿全部进行中课堂），然后**按课程名过滤**：
  `live = [x for x in live if subj in str(x.get("title") or "")]`（`live_all` 的 `title` 就是 courseName）。
- **让位规则**：全局通配任务（`classroom_id='*'` 且无 subject）执行前先查本人 `state='active'` 的 `subj:%` 任务；存在则 `continue`。即「一旦勾了具体课程，全局巡检就不再顺手把别的课签了」；所有课程任务都暂停/删掉后，全局通配自动恢复接管。这条规则保证「一门都不勾 = 全签」。
- 考勤回读、`PEND` 指数退避、`OK_AT` 冷却逻辑对课程任务完全复用，不需要改。

## 接口（app.py）
- `POST /api/app/course/prefs {acct?}` → `{ok, acct, courses:[{subject,cid,meets:[{wd,start}],total,on,noTT?}], watch, any, err}`
  - 数据源：`S().timetable(acct, days)` 的 `slots` 按 `subject` 聚合，`total` 是已上课次数，`meets` 取前 6 个「周X 时间」。
  - 已建的课程任务即使课表为空也会补进列表（`noTT:true`），否则换设备/会话过期时用户看不到自己勾过的课。
  - `watch` = 全局通配是否在跑；`any` = 是否有课程任务在跑。
- `POST /api/app/course/toggle {subject, on}` → `{ok, id, subject, on}`
  - 已存在则 UPDATE state；不存在则 INSERT（`title='自动签到 · 课程名'`、`win_start/win_end/quiz/geo` 继承全局任务，没有全局任务时默认 00:00–23:59 / quiz=1 / geo=1）。
  - 写 `biz.event("watch", "勾选课程自动签到"/"取消课程自动签到", detail=课程名)`。

## 前端（web2）
巡检页在「巡检策略」和「课堂级任务」之间新增一张卡「按课程自动签到」：
- 文案：`勾选的课程才自动签到；一门都不勾 = 所有进行中课堂都签`
- `loadCourses()` 拉 `app/course/prefs`，按 `total` 倒序渲染 `课程名 + 周X 时间 · 已上 N 次 + 开关`；
- 开关 change → `app/course/toggle` → 成功后重新 `loadCourses()`；失败回滚勾选并 alert。
- 课表为空（雨课堂会话过期）时提示：`还没拿到课程列表：雨课堂会话可能已过期，去「绑定」页重新扫码后再回来`。
- `loadTasks()` 过滤条件从 `classroom_id !== '*'` 扩成 `!== '*'` 且 `indexOf('subj:') !== 0`，课程任务不会再混进「课堂级任务」列表。

## 部署与验证
固定流程：上传 app.py/biz.py 与 web2 静态 → `python3 -m py_compile` → `bash /opt/yktsign-build/build_secure.sh`（imports ok / bytecode deployed: 14 modules）→ `systemctl restart ykt-svc ykt-web`。

实测（2026-11-16）：
- `course/toggle {subject:"大学物理C",on:true}` → `{"ok":true,"id":7}`；库里 `id=7 acct=main classroom_id=subj:大学物理C state=active`。
- 前端点开关 → 关闭返回 `paused`、勾选态取消；再点开 → `active`。截图 `shots/watch-courses.png`。
- `course/prefs` 在课表为空时仍回 `courses:[{subject:"大学物理C",noTT:true,on:true}]`，卡片不空白。

## 已知阻塞：main 账号雨课堂会话已过期
`server.ykt(GET, /v2/api/web/logs/learn/26000003)` 回 `401 {"errcode":401000,"errmsg":"Session not exists"}`，`/api/v3/classroom/on-lesson-upcoming-exam` 回 `code:50000 UNAUTHENTICATED`。后果：`timetable("main") → slots 0`，所以线上课程列表暂时是空的（只剩已勾过的那门）。恢复方式：`https://example.com/ykt/u/#/bind` → 微信扫码 → 输入微信里收到的 4 位数字。注意 `qrlogin.finish()` 会新建/改名 acct 并绑定 owner，可能与现有 `tasks.acct='main'` 脱节（见待办 ④ 多账号扫码/续期入口）。
