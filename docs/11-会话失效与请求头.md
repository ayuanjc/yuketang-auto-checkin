# 11 · 会话失效与请求头排障（2026-11）

## 1. 症状

2026-11-16 16:5x 起，同一份 cookie 出现「分裂」状态：

| 接口 | 结果 |
| --- | --- |
| `GET /v2/api/web/courses/list?identity=2` | 200，52 门课 |
| `GET /api/v3/user/basic-info` | `{"code":50000,"msg":"UNAUTHENTICATED"}` |
| `GET /api/v3/classroom/on-lesson-upcoming-exam` | 同上 |
| `GET /api/v3/classroom/lesson-config` | 同上 |
| `POST /api/v3/lesson/checkin` | 同上 |

定时任务因此每 20 秒写一条失败 run，页面显示「会话失效：需重新扫码」。

## 2. 排除项

- **不是 cookie 缺字段**：浏览器里用同一 cookie 直接 `fetch('/api/v3/user/basic-info')` 也返回 50000（当时的观察）。
- **不是 localStorage token**：站点 localStorage 只有 `vuex`、`user_profile`、`pgv_*`，无 access token。
- **不是 sid 缺失**：新版 web 登录只下发 `csrftoken` + `sessionid` + `django_language`，本来就没有 `sid`。

## 3. 根因：老桌面头被新版 web 会话拒绝

同一 cookie，只改请求头（`GET /api/v3/user/basic-info`）：

| 请求头组合 | 返回 |
| --- | --- |
| 仅 Cookie | `code 0` |
| Cookie + `xtbz: ykt` | `code 0` |
| Cookie + `Referer: https://changjiang.yuketang.cn/v2/web/index` | `code 0` |
| Cookie + `Origin: file://` + `xtbz: ykt`（无 desktop） | `code 0` |
| Cookie + `X-Client: web` + `xtbz: ykt` | `code 0` |
| Cookie + `xtbz: ykt` + `desktop-v: v2` + `X-Client: desktop` | **`code 401 登录失效，请重新登录`** |
| 上一行 + `Origin: file://` | **401** |

带桌面头的 `POST /api/v3/lesson/checkin {source:5, lessonId}` → 401；
换成 `xtbz: ykt` + 同源 `Referer` → `{"code":0,"msg":"OK","data":{"role":5,…,"lessonToken":"eyJ…"}}`。

结论：2026-11 之后，雨课堂对**新版 web 会话**（sessionid 来自 /web 登录页）不再接受老桌面客户端标识；桌面头仅对真正以 desktop 方式登录的会话有效。

## 4. 代码改动

`scripts/server.py` · `ykt()` 的非 app 分支：

```python
headers = {"User-Agent": UA, "xtbz": "ykt", "Accept": "application/json, text/plain, */*"}
if os.environ.get("YKT_DESKTOP", "0") == "1":
    headers.update({"desktop-v": "v2", "X-Client": "desktop", "Origin": "file://"})
else:
    headers["Referer"] = "https://" + domain + "/v2/web/index"
```

- 默认走 web 会话头（Referer 同源）。
- 需要回到老桌面头时：systemd drop-in 里加 `Environment=YKT_DESKTOP=1` 再重启，用于排查历史行。
- `app=True` 分支（`x-client: app` + Android UA）不动：`/api/v3/app/scan` 等 app 专属端点只认这套头。

## 5. 另一条死路：服务端扫码登录

- `GET /api/v3/user/login/pre-info` 返回的 `qrImage` 是**微信公众平台临时二维码**（`mp.weixin.qq.com/cgi-bin/showqrcode?ticket=…`，430×430 JPEG），不是雨课堂自己的登录码。
- 用户用微信扫该码 → 微信侧提示「登陆失败」（未关注公众号 / ticket 已失效都会这样）。
- 轮询脚本另有一个 bug：把 `wait-for-scan` 响应 `[:200]` 截断，导致 `data.token`（校验用 JWT）被切断，提交 `login-with-code` 时 `json.decoder.JSONDecodeError: Unterminated string starting at: line 1 column 36`。
- 同一 token **只能长轮询一次**，第二次直接 `400 {"code":50400,"msg":"BAD_REQUEST"}`；`data.token` 的 JWT `exp = iat + 60s`，60 秒内必须提交 4 位数字。
- **可用路径**：真实浏览器打开 `https://changjiang.yuketang.cn/web?next=/v2/web/index&type=3` → 手动登录（`/v2/web/login` 是死链）→ `Network.getAllCookies` 取 3 个 cookie → 写入 `cookies.json`。

## 6. 调度器配套改动（`scripts/app.py`）

- `OK_AT`（成功冷却 **900s**，按 `(acct, lid)`）、`NEED_LOGIN`（会话失效账号 **600s** 内跳过）。
- `umauth(detail)` = `'"code":50000' in detail`；命中时写 run「会话失效 code=50000：该账号雨课堂登录已过期，需要重新扫码登录」，并把 `tasks.last_result` 置为「会话失效：需重新扫码」（30 分钟内只写一次，避免刷屏）。
- `/api/app/accts` 每项带 `need_login`；前端账号卡显示「需重新登录」标签 + 恢复提示。

## 7. 运维坑（踩过，务必记住）

1. **manifest 只能是 basename**：`/opt/yktsign-build/manifest.sha256` 每行必须是 `<sha256>  <文件名>`，共 10 行、`chmod 600`。给它加路径前缀会让 `secure.verify_manifest()` 失败 → 进程 `exit 66/NOINPUT`、systemd 无限重启。
   重建：`cd /opt/yktsign && sha256sum secure.pyc server.pyc loc.pyc ai.pyc svcclient.pyc biz.pyc app.pyc svc.pyc web.pyc lesson_watch.pyc > /opt/yktsign-build/manifest.sha256`
   校验：必须 `cd /opt/yktsign` 再 `sha256sum -c /opt/yktsign-build/manifest.sha256`（相对路径解析）。
2. **8080 残留进程**：`ykt-web` 报 `OSError: [Errno 98] Address already in use` 说明有历史 `server.py 8080` 进程（PPID=1）没退；`ss -ltnp | grep :8080` 找 pid → `kill -9` → `systemctl start ykt-web`。
3. **部署固定流程**：上传 `.py` 到 `/opt/yktsign` → `bash /opt/yktsign-build/build_secure.sh`（`imports ok` / `bytecode deployed: 10 modules`）→ `systemctl restart ykt-svc ykt-web`。静态前端（`app_web/`）直接 scp 覆盖，不在字节码构建范围。
