## 1. 进程与信任边界

```
浏览器 ──HTTPS──▶ nginx(443) ──/ykt/──▶ web.py 127.0.0.1:8080   唯一对外进程（会话/页面/参数校验）
                                            │
                                            └── X-Svc-Token ──▶ svc.py 127.0.0.1:8090   协议核心（雨课堂 API/签到/动态码/位置/watcher）
```

- web.py 不含协议实现：拿下它拿不到协议细节，只是会话层。
- svc 的 `/raw` 只放行 `/api/v3/ /api/v2/ /v2/api/ /api/web/ /api/v1/`，其余 403，避免被当任意代理。
- token：`/opt/yktsign/svc_token.txt`（0600，48 字符）。

## 2. 落盘加密（secure.py）

- AES-256-GCM，12B 随机 nonce；信封 `{"_enc":"enc.v1","n":b64,"d":b64,"at":ts}`；key = `secret.key`（32B，0600）。
- 覆盖 cookies.json、accounts/*.json、lesson_auth*.json、ai.json。
- `secure.migrate_all()` 在 svc 启动时幂等加密旧明文，原文件直接覆盖，不留明文备份。
- **备份纪律**：丢 secret.key 等于全部凭据不可解（只能重新扫码）。必须同批备份：
  ```bash
  tar -czf /root/ykt-secrets-$(date +%F).tgz -C /opt/yktsign secret.key cookies.json ai.json accounts lesson_auth*.json 2>/dev/null
  chmod 600 /root/ykt-secrets-*.tgz
  ```

## 3. 完整性校验 / 反注入（secure.boot → harden + guard）

| 检测点 | 实现 | 结果 |
|---|---|---|
| ptrace / gdb attach | /proc/self/status 的 TracerPid ≠ 0 | 3s 内 exit 66 |
| core dump 取证 | prctl(PR_SET_DUMPABLE,0) + RLIMIT_CORE=0 | 无 core 可拿 |
| frida/xposed 注入 | 扫 /proc/self/maps：frida-agent、frida-gadget、libfrida、gum-js-loop、gdbserver、lldb-server、pydevd | 同上 |
| Python 调试器 | sys.modules 含 pydevd/pdb/bdb/frida/ptrace/gdbserver | 启动即拒 |
| trace 钩子 | sys.settrace / setprofile / breakpointhook 被替换成 suicide() | 调用即 exit 66 |
| 环境注入 | PYTHONINSPECT/PYTHONSTARTUP/PYTHONBREAKPOINT/PYDEVD/YPDB/LD_PRELOAD/LD_AUDIT | 启动即拒 |
| 单步断点 | 扫所有线程 frame 的 f_trace（gettrace 是线程局部，只看主线程会漏） | 3s 内 exit 66 |

实测：`sys.settrace(...)` → exit 66；`import pydevd; secure.boot()` → exit 66；正常启动 `boot ok`。

## 4. 发行形态：只发字节码

```bash
# 改代码的唯一正确姿势：把 .py 传到 /opt/yktsign，然后
bash /opt/yktsign-build/build_secure.sh           # -OO 编译、删 .py、重写 manifest
bash /opt/yktsign-build/build_secure.sh --restore # 排障回滚成 .py
systemctl restart ykt-svc ykt-web
```

- `compileall -b`（legacy 布局，无 __pycache__）+ `python3 -OO`（去 docstring、去 assert）。
- build 第 1 步会把线上 .py 收进 /opt/yktsign-src，所以「上传 .py → build」是唯一流程；直接改 pyc 会被完整性检查打死。
- 启动器：`/opt/yktsign-build/boot_svc.sh`、`boot_web.sh`：
  ```sh
  exec /usr/bin/python3 -OO -c "import sys;sys.path.insert(0,'/opt/yktsign');import web;web.main()" 8080 127.0.0.1
  ```
- watcher：svc.py 优先起 `lesson_watch.pyc`（`python3 x.pyc` 可直接执行）。
- 外部请求 `/ykt/web.pyc` → 403。

## 5. 完整性校验

- `build_secure.sh` 生成 `/opt/yktsign-build/manifest.sha256`（10 行，0600）。
- `secure.boot()` → `verify_manifest()`：任一 pyc 不符 → `E: integrity <module>` + `os._exit(66)`，systemd 看到 `status=66/NOINPUT` 并可熔断。
- 手工复验：`sha256sum -c /opt/yktsign-build/manifest.sha256`（当前 10/10 OK）。

## 6. Web 层（web.py）

1. CSRF：`_origin_ok()` 要求 Origin/Referer 的 netloc == Host，否则 403（无 Origin 的内部调用放行）。
2. 体积：MAXBODY=256KB → 413。
3. 登录：**先验密码**，正确一律放行；只有失败才计数（IP+用户名，8 次/300s），超限 429。这样外部请求方无法用错密码把管理员锁死。
4. 注册：同 IP 8 次/300s。
5. 穿越：`/app/` 拒绝 `..`；DENY 黑名单兜底 cookies/key/ai.json/svc_token/.db/.py/.pyc/accounts/secret/events。
6. 响应头：nosniff、SAMEORIGIN、Referrer-Policy、`Cache-Control: no-store`。
7. Cookie：HttpOnly + Secure + SameSite=Lax（因此本地 http 调试拿不到会话，属预期，用 https 测）。

## 7. nginx（snippets/yktsign.conf + ykt-proxy.inc + ykt-headers.inc）

- 限流：`yktapi 180r/m burst=120`、`yktlogin 10r/m burst=5`、`limit_conn yktconn 24`。
- deny：`\.(py|pyc|pyd|pyo|db|sqlite3?|key|pem|crt|log|sql|sh|bak|old|swp|tar|gz|zip)$`、`/(accounts|events|__pycache__)(/|$)`、`(cookies|lesson_auth|scan_exchange|svc_token|secret)…`。
- 反代：`proxy_hide_header Server/X-Powered-By`、35s 读超时、8m 体限、X-Forwarded-Proto。
- 头：`Permissions-Policy "camera=(self), geolocation=(self), microphone=()"`（扫码要摄像头，别照抄主站的 camera=()）、`X-Robots-Tag noindex`。
- 坑：`location` 里 proxy_pass 用显式 URI（`…/api/biz/login`）；若与带 URI 的 include 共用，nginx 会用 URI 替换整个 location 前缀，上游收到错路径（表现为 403 bad key）。

## 8. systemd 最小权限（drop-in）

`/etc/systemd/system/ykt-{svc,web}.service.d/hardening.conf`：

```
UMask=0077  PrivateTmp=yes  PrivateDevices=yes
ProtectSystem=full  ProtectHome=yes  ReadWritePaths=/opt/yktsign
ProtectKernelTunables/Modules/Logs=yes  ProtectControlGroups/Clock/Hostname=yes
ProtectProc=invisible  ProcSubset=pid
RestrictSUIDSGID/Namespaces/Realtime=yes  LockPersonality=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
SystemCallArchitectures=native  SystemCallFilter=@system-service  SystemCallErrorNumber=EPERM
```

加固后回归：login 200、courses 52、checkin code 0、watch start/stop 正常、页面 200。

## 9. 剩余风险

1. 字节码不是保险箱：`dis` 仍可读；商业级需 PyArmor/原生扩展（会影响 Restart 与 CI，本轮未做）。
2. 进程内可读 secret.key：能登 root 即可解密。下一步 TPM/独立密钥守护进程。
3. 雨课堂侧上游限流：多账号同 IP 高频签到是最大暴露面，与完整性无关但更致命。
4. 账密登录已废（腾讯防水墙 300416），只剩扫码，无密码暴露面。
5. 日志 `login failed ip=… user=…` 落 journal（不含密码）。
