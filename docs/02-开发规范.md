# ykt-ops 开发规范

> 强制项标 **[M]**（CI 拦截），建议项标 [S]。评审时只对 [M] 做阻塞性评论。

---

## 1. 仓库结构

```
ykt-ops/
├── cmd/
│   ├── api/          # HTTP 服务入口
│   ├── scheduler/    # 定时调度入口
│   └── agent/        # 长连接执行器入口
├── internal/
│   ├── domain/       # 纯业务类型与规则（零外部 import）
│   ├── ykt/          # 雨课堂协议层
│   │   ├── protocol/ # wire DTO + 端点常量
│   │   └── profile/  # 域名族差异
│   ├── store/        # 仓储 port + pg/memory 实现
│   ├── queue/        # 队列 port + redis/memory 实现
│   ├── llm/          # 答题 provider + 投票
│   ├── proxy/        # 出口代理池
│   ├── crypto/       # 信封加密
│   ├── obs/          # 日志/指标/脱敏
│   ├── httpx/        # 路由/信封/中间件
│   └── config/       # 环境变量
├── deploy/           # compose / Dockerfile / nginx / sql 迁移
├── docs/             # 本目录
└── testdata/         # 协议 fixture（wss 帧录制）
```

**[M] 禁止**在 `internal/` 下出现 `utils`、`common`、`helpers`、`base` 这类无名包。放不进去就说明领域没想清楚，先回 `domain/`。

---

## 2. 依赖规则（CI 用 `go list` 校验）

| 包 | 允许 import |
|---|---|
| `domain` | 仅 stdlib |
| `ykt/*` | stdlib + `domain` + `obs` |
| `store`、`queue`、`llm`、`proxy` | stdlib + `domain` + `obs` |
| `httpx` | stdlib + `domain` + `obs` |
| `cmd/*` | 任意 |

**[M]** `ykt`、`store`、`queue`、`llm`、`proxy` 不得 import `httpx`（反向依赖禁止）。
**[M]** 只在 `cmd/*` 里 `new` 具体实现；内部传播一律用接口。

---

## 3. 命名

**[M]**
- 包名：小写单词、无下划线、无复数（`store` 不是 `stores`）。
- 接口：能力名（`AccountRepo`、`Queue`），单方法接口用 `-er`（`Signer`）。
- 实现：`pgAccountRepo`、`redisQueue`、`memoryQueue`（不导出）。
- 错误哨兵：`ErrXxx`，包内 `var ErrXxx = errors.New(...)`。
- 时间字段一律 `...At`（`CreatedAt`、`DeadlineAt`），`time.Time` 存 UTC。
- 布尔字段不带 `Is` 前缀（`Enabled` 不是 `IsEnabled`）。
- 上下文参数永远第一个、叫 `ctx`。

**[S]** 缩写表：`cfg`、`repo`、`sess`、`pwd` 之外不缩写；`checkin` 保持雨课堂原词拼写（不要写成 `checkIn`），`lessonId` 在 wire DTO 里保持服务端命名，在 domain 里用 `LessonID`。

---

## 4. 错误处理

**[M]**
1. 错误必须带上下文：`fmt.Errorf("checkin lesson %d: %w", id, err)`。
2. 用 `errors.Is/As` 判断，禁止字符串匹配错误信息。
3. 对外错误面统一走 `httpx` 的错误映射表，**不得把内部错误文本直接回显给用户**。
4. 不允许吞错：`if err != nil { /* ignore */ }` 必须写注释说明为什么安全。
5. `panic` 只允许在 `init`/启动期（配置非法时 fail fast）。

错误码分段见 `04-接口约定.md`。

---

## 5. 日志与脱敏

**[M]** 统一 `log/slog` + JSON handler，字段名固定：

```
ts level msg  request_id  trace_id  user_id  account_id  lesson_id  task_id  domain  duration_ms  err
```

**[M] 强制脱敏**：`obs.Redact` 在 handler 层执行，命中以下键名一律替换为 `***`：
`cookie`、`set-cookie`、`authorization`、`set-auth`、`csrftoken`、`sessionid`、`password`、`ticket`、`s`（签名字段）、`api_key`、`token`。

**[M]** 禁止在日志中打印完整 URL 查询串（含 `t`/`s` 签名）。需要留证时用 `obs.URLFingerprint(u)`（保留 host+path，query 只留键名）。

**[M]** 用户可见文案与日志分开：日志写英文，UI 文案写中文。

---

## 6. 协议层规范（最容易出错的地方）

**[M]**
1. **端点常量集中在** `internal/ykt/protocol/endpoints.go`，一处改动，禁止散落字符串。
2. **域名族差异只许放在 `profile/`**：`source` 取值、必带 header（`xtbz: ykt` 等）、字段名映射。业务代码读到的是 `domain` 类型，不是 map。
3. **每个 profile 必须有对应文档** `docs/protocol/<domain>.md`：端点表 + 请求/响应样例（脱敏）+ 版本时间戳 + 已知坑。
4. **魔法数禁用**：`source: 5` 必须写成 `profile.CheckinSource`。
5. **wire DTO 与 domain 分离**：`protocol` 里的结构体只用于序列化，转换函数 `toDomain()` 单独测试。
6. **所有出站请求必须**：
   - 带 `ctx` 超时（默认 3s，签到链总预算 25s）
   - 带 `request_id`（透传到雨课堂无效，但用于本地串联）
   - 经 `ykt.Client` 统一出口（禁裸 `http.Get`），以保证 UA 池、代理、限速、留证一致生效
7. **WSS 帧处理必须幂等**：同 `problemId` 重复下发只作答一次（`answered` 集合 + DB 唯一索引双保险）。
8. **时钟**：所有 deadline 判断用 `Clock`（`obs.Clock`），生产实现按帧 `dt` 校正偏移，测试注入固定时钟。

## 7. 测试规范

**[M]**
- `domain` 覆盖率 ≥ 85%，其余 ≥ 60%。
- `ykt` 层用 **fixture 回放**：`testdata/<domain>/<scenario>.jsonl` 存录制的 wss 帧与 HTTP 响应，测试时用 `replayer` 喂给 handler，断言动作序列（签到次数、提交内容、时间点）。
- 每个 bug 修复必须补一个失败复现用例。
- 禁止在测试里访问真实雨课堂；需要端到端时用 `faketang`（`internal/ykt/faketang`，本地 httptest + websocket 假服务端）。

**[S]** 表驱动优于分支；`t.Parallel()` 默认加；测试名写行为（`TestSignPolicy_FallsBackToDynamicCode`）。

可靠性用例清单（每次发版必跑）：
1. 签到请求 500 后重试仍成功
2. 同 lesson 重复任务只提交一次
3. lesson 结束后到达的任务直接放弃，不重试
4. deadline 前 8s 一定有一次提交尝试
5. wss 断线后 5s 内重连且 lessonToken 复用
6. 帧时间戳倒退不导致负等待
7. 凭据解密失败不 panic、不阻塞其他账号

## 8. Git 与评审

**[M]**
- 主干开发：`main` 常绿，短分支 `feat/xxx` `fix/xxx`，存活 ≤ 3 天。
- 提交信息 Conventional Commits：`feat(agent): 支持动态码签到回退`，body 写"为什么"。
- 一个 PR 一个关注点，diff ≤ 400 行为宜。
- PR 必须包含：变更动机、影响面（哪些进程/表/端点）、回滚方式、测试证据。

PR 自检清单：
- [ ] 没有新增硬编码端点/魔法数
- [ ] 新增日志字段都通过 Redact
- [ ] 新协议行为有 fixture 用例
- [ ] 数据库变更带可回滚迁移
- [ ] 影响部署的变更更新了 `docs/05-部署运维.md`

**[M] 禁止提交**：`.env`、`*.pem`、抓包文件、真实 cookie、真实学号姓名。

## 9. 代码风格与工具

| 工具 | 配置 | 说明 |
|---|---|---|
| `gofmt` | 默认 | **[M]** CI 校验 |
| `goimports` | `-local yktops` | 分组：标准库 / 三方 / 本项目 |
| `golangci-lint` | `.golangci.yml` | 启用 errcheck, govet, staticcheck, revive, gosec, bodyclose, sqlclosecheck, contextcheck, exhaustive |
| `gosec` | 默认 | **[M]** 高危项（G402/G404/G501）为 error |
| `go vet` | 默认 | **[M]** |

其他约定：
- **[M]** 导出符号必须有注释，首词为符号名。
- **[M]** 函数 ≤ 60 行，圈复杂度 ≤ 12（超过就拆）。
- **[S]** 提前返回优于嵌套；不写 `else` after `return`。
- **[S]** 不用 `interface{}`，用 `any`；不用 `init()` 做业务初始化。
- **[M]** 所有 IO 函数第一参数 `ctx context.Context`。

## 10. CI 流水线（GitHub Actions / 自建 runner 均可）

```
1. gofmt -l . | tee /dev/stderr | wc -l  → 必须为 0
2. go vet ./...
3. golangci-lint run
4. go test -race -count=1 -coverprofile=cover.out ./...   （覆盖率阈值校验）
5. go list 依赖规则校验脚本 ./scripts/arch_check.sh
6. go build -trimpath -ldflags "-s -w -X main.version=$GIT_SHA" ./cmd/...
7. docker build（多阶段，产物 < 30MB）
8. 冒烟：docker compose up faketang + api + agent → 跑 tests/e2e
```

**[M]** 步骤 1~6 任一失败禁止合入。

---

## 11. 配置与密钥

**[M]**
- 全部配置走环境变量，`config.Load()` 启动时校验并打印**非敏感**摘要。
- 变量前缀 `YKT_`，清单见 `.env.example`；新增变量必须同步 `.env.example` 与 `docs/05-部署运维.md`。
- 密钥类（`YKT_MASTER_KEY`、`YKT_DB_DSN`、`YKT_LLM_*_KEY`）只从环境/secret 文件读，**无默认值**，缺失直接退出。
- 本地开发用 `deploy/.env.dev`（已 gitignore）。

---

## 12. 变更风险分级

| 级别 | 例子 | 要求 |
|---|---|---|
| P0 | 协议端点/字段、加密、计费 | 双人评审 + fixture 用例 + 灰度一域名族 |
| P1 | 调度策略、答题投票 | 双人评审 + 回滚脚本 |
| P2 | UI、日志字段 | 单人评审 |

**[M]** P0 变更必须在 PR 描述里写明"如果线上炸了，怎么在 5 分钟内回滚"。
